# 노트 생성

`POST /notes` 한 번으로 제목과 본문을 남기고, 생성된 id와 시각을 돌려받는다.

## Problem

알아낸 것을 남길 곳이 없다. 위키는 폴더·태그·템플릿을 요구하고, 채팅은 받아주지만 되찾을 수 없다. Jun은 장애 중이라 둘 다 못 쓴다.

## Value

입력 비용이 curl 한 줄로 떨어진다. 노트가 한 곳에 쌓이기 시작해야 002(목록)·003(검색)이 의미를 갖는다 — 이 기능이 나머지 둘의 전제다.

## Solution

`POST /notes`에 `{"title","body"}` JSON을 보내면 201과 `{id,title,body,created_at}`을 받는다. `title`·`body`는 필수이고 공백만 있는 값은 거부한다. 검증 실패는 400과 `{"error":{"code","message"}}`로 이유를 말한다 — 조용히 자르거나 버리지 않는다(PROJECT 원칙 3).

## Scope

**Includes:**
- `POST /notes` 라우트, service 검증, repository INSERT
- `notes` 테이블 스키마와 마이그레이션
- 400 에러 포맷

**Excludes:**
- 수정·삭제, 태그·폴더, 첨부파일
- 인증·권한(내부망 전용)
- 목록·검색(002·003)

## User Stories & Acceptance Criteria

### Story 1: 남긴다

**As a** Mina, **I want** curl 한 줄로 메모를 저장하고 **so that** 같은 삽질을 반복하지 않는다.

**Scenario:**
- Given: 서비스가 떠 있고 DB가 비어 있다
- When: `POST /notes {"title":"pg pool leak","body":"max=10이면 ..."}`
- Then: 201과 `{id, title, body, created_at}`이 돌아오고, 그 id로 DB에 행이 하나 있다

**Acceptance Criteria:**
- [ ] 유효한 요청은 201과 생성된 id를 반환한다 — verify: integration (level: full)
- [ ] 반환된 `created_at`은 고정 시계 기준 요청 시각이다 — verify: unit, fake timers (level: fast)
- [ ] 저장된 행의 title/body가 요청과 동일하다(트림 후) — verify: integration (level: full)

**Edge Cases & Errors:**
- [ ] `title` 누락/공백만 → 400 `invalid_request`, 행이 생기지 않는다 — verify: unit + integration (level: full)
- [ ] `body` 누락/공백만 → 400 `invalid_request` — verify: unit (level: fast)
- [ ] JSON이 아닌 body → 400, 500이 아니다 — verify: integration (level: full)
