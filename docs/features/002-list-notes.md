# 노트 목록

> **Status: backlog.** 백로그 이슈 #5로 대기 중이다. `main`에는 이 기능의 코드가 없다.

`GET /notes`로 최신순 노트를 페이지 단위로 훑는다.

## Problem

노트를 남기기 시작해도 무엇이 쌓였는지 볼 방법이 없다. Sora는 주 1회 "최근에 무슨 일이 있었나"를 훑고 싶은데, 검색어를 아직 모른다 — 검색(003)만으로는 이 요구를 못 채운다.

## Value

쌓인 것을 눈으로 확인할 수 있어야 노트가 팀의 기록이 된다. 003 검색의 응답 형식도 여기서 정의된 `{items,total}`을 그대로 쓴다 — 두 번 설계하지 않는다.

## Solution

`GET /notes?limit=&offset=`가 `created_at DESC, id DESC` 정렬로 `{items:[...], total}`을 반환한다. `limit` 기본 20, 최대 100. 범위를 벗어난 값은 400이 아니라 상한으로 잘라 쓰되, 음수·비정수는 400이다.

## Scope

**Includes:**
- `GET /notes` 라우트, limit/offset 파싱과 상한
- 안정 정렬(`created_at DESC, id DESC`)
- `total` 카운트

**Excludes:**
- 검색어 필터(003)
- 커서 기반 페이지네이션, 정렬 옵션
- 필드 선택(sparse fieldsets)
