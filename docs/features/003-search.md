# 노트 검색

`GET /notes?q=`로 제목·본문을 부분일치 검색해 되찾는다.

## Problem

노트가 쌓일수록 목록 훑기로는 못 찾는다. Mina는 3개월 전 자기 메모를 단어 하나로 되찾고 싶은데, 지금은 페이지를 넘기는 수밖에 없다. **되찾기가 기능의 절반**(PROJECT 원칙 2)인데 그 절반이 없다.

## Value

검색이 붙는 순간 노트는 "남기는 곳"에서 "쓰는 곳"이 된다. MVP 성공 지표(검색 후 재열람 비율 ≥ 30%)가 이 기능에 직접 걸려 있다.

## Solution

`GET /notes?q=pool`이 `title ILIKE '%pool%' OR body ILIKE '%pool%'`인 행을 002와 동일한 `{items,total}` 형식·동일한 정렬·동일한 페이지네이션으로 반환한다. `q`는 트림하고, `%`·`_`는 리터럴로 이스케이프한다(와일드카드 주입 금지). 빈 `q`는 필터 없음(=002와 동일)으로 취급한다.

## Scope

**Includes:**
- `q` 파라미터 파싱·트림·LIKE 이스케이프
- 대소문자 무시 부분일치(`ILIKE`), title/body 양쪽
- 002의 limit/offset·정렬 재사용

**Excludes:**
- 형태소·전문 검색(`tsvector`) — TDR-2의 fallback으로 별도 이슈
- 필드 지정 검색(`title:foo`), 불리언 연산자, 하이라이팅
- 랭킹(관련도 정렬) — 정렬은 최신순 고정
