# 응답 캐시 만료

`GET /notes` 응답을 쿼리 문자열 기준 5초간 인메모리로 캐싱하고, 쓰기가 있으면 즉시 무효화한다.

## Problem

Mina가 스크립트에서 같은 `GET /notes?...`를 짧은 간격으로 반복 호출할 때마다 DB를 다시 훑는다. 002/003이 커버하는 조회 자체는 옳지만, 반복 조회 비용은 아직 아무도 줄이지 않았다.

## Value

동일 쿼리의 반복 호출이 DB를 건드리지 않아 p95가 안정된다. TECHNICAL의 검색 성능 제약(003, p95 < 200ms @ 1k건)을 반복 호출 구간에서 지켜주는 안전판이다.

## Solution

`GET /notes`(쿼리 유무 무관, 002·003 모두 대상)의 응답을 프로세스 메모리에 쿼리 문자열을 키로 5초간 캐싱한다. `POST /notes`가 201로 성공하면 캐시 전체를 무효화한다. TTL은 고정 5000ms이고, 만료 후 첫 요청은 DB를 다시 조회해 새로 캐싱한다. 시계는 주입 가능해야 한다 — QA.md 결정성 규칙상 테스트가 `setTimeout`으로 실제 5초를 기다려서는 안 된다.

## Scope

**Includes:**
- 쿼리 문자열 키 기반 인메모리 캐시, TTL 5000ms
- `POST /notes` 성공 시 전체 무효화
- 주입 가능한 clock(기본 `Date.now`)

**Excludes:**
- 다중 프로세스/외부 캐시(Redis 등) — 단일 프로세스 전제
- 부분 무효화(영향받는 키만 지우기) — 전체 무효화로 단순화
- 캐시 크기 제한, LRU 축출

## User Stories & Acceptance Criteria

### Story 1: 반복 조회가 DB를 다시 건드리지 않는다

**As a** Mina, **I want** 같은 조회를 5초 안에 반복해도 캐시된 응답을 받아 **so that** 스크립트가 DB에 부담을 주지 않는다.

**Scenario:**
- Given: 고정 시각 T에 `GET /notes?limit=10`을 호출해 응답을 받았다
- When: T+2s에 동일한 쿼리로 다시 호출한다
- Then: DB를 다시 조회하지 않고 캐시된 동일 응답을 반환한다

**Acceptance Criteria:**
- [ ] 동일 쿼리 문자열로 5초 이내 재요청하면 캐시된 응답을 반환한다 — verify: integration, `vi.useFakeTimers({ now: ... })`로 시각 고정 (level: full)
- [ ] 캐시 키 생성(쿼리 문자열 정규화)과 TTL 만료 판정이 주입된 clock으로 DB 없이 검증된다 — verify: unit, `vi.useFakeTimers()` (level: fast)
- [ ] `POST /notes` 성공 직후 `GET /notes`가 캐시가 아닌 새 데이터를 반환한다 — verify: integration, fake timers (level: full)

**Edge Cases & Errors:**
- [ ] TTL(5000ms) 경과 후 요청은 캐시를 쓰지 않고 DB를 다시 조회한다 — verify: unit, `vi.advanceTimersByTime(5001)`. 실제 `setTimeout`/wall-clock 대기(sleep)로 검증하지 않는다(QA.md No sleep 규칙) (level: fast)
- [ ] `limit`/`offset`/`q`가 다르면 별도 캐시 키로 취급되어 서로 캐시를 공유하지 않는다 — verify: unit (level: fast)
- [ ] `POST /notes`가 400으로 실패하면 캐시를 무효화하지 않는다 — verify: integration, fake timers (level: full)

## Design Intent

| Step | User Action | Ideal Outcome | Design Decision | QA Verification |
|------|-------------|---------------|-----------------|-----------------|
| 1 | 같은 쿼리 반복 | 즉시 응답 | TTL 5초 인메모리 캐시 — 외부 캐시는 과설계 | 두 번째 호출이 DB 스파이를 호출하지 않음 |
| 2 | 새 노트 작성 후 조회 | 방금 쓴 것이 바로 보인다 | 쓰기 시 전체 무효화 — 부분 무효화는 과설계 | POST 직후 GET이 새 항목 포함 |

| State | Trigger | User Sees |
|-------|---------|-----------|
| Cache hit | TTL 내 동일 쿼리 | 이전과 동일한 `{items,total}`, DB 재조회 없음 |
| Cache miss(만료) | TTL 경과 후 요청 | DB를 다시 조회한 최신 `{items,total}` |
