# ADR-001 settings.json 훅의 Workflow 서브에이전트 적용

- PreToolUse(Bash) in workflow agents: yes (라인 수 8 — `spike-hooks-dispatch` 실행 전체에서 발화한 `PreToolUse\tBash\t...` 라인 수. 워커 2명이 각자 지시받은 `echo SPIKE_WORKER_BASH_<n>` 외에 워크플로/디스패처 경로의 부수 Bash 호출(mkdir/ls/touch 등)도 함께 잡혔다. `test -f .spike/worker-1.txt && test -f .spike/worker-2.txt`도 통과해 각 워커가 지시된 파일을 실제로 Write 툴로 생성했음을 확인. `SubagentStart`/`PreToolUse` 모두 ≥2로, 브리프가 정의한 "적용됨" 기준을 충족.)
- SubagentStart/Stop: yes · 식별 필드: [agent_id, agent_type] (SubagentStart 2줄, 키 목록 `["agent_id","agent_type","cwd","hook_event_name","prompt_id","session_id","transcript_path"]`; SubagentStop 2줄, 키 목록 `["agent_id","agent_transcript_path","agent_type","background_tasks","cwd","effort","hook_event_name","permission_mode","prompt_id","session_crons","session_id","stop_hook_active","transcript_path"]` — SubagentStop에는 `agent_transcript_path`가 추가로 있음. 워커 2명 = SubagentStart 2줄·SubagentStop 2줄로 정확히 대응. 또한 모든 `PreToolUse`(Bash/Write/Read) 이벤트 자체도 `agent_id`·`agent_type` 키를 포함하고 있어, 훅 페이로드만으로 툴 호출 단위까지 서브에이전트 귀속이 가능함을 확인. 반면 메인 세션 `Stop` 이벤트(2줄, 키 목록 `["background_tasks","cwd","effort","hook_event_name","last_assistant_message","permission_mode","prompt_id","session_crons","session_id","stop_hook_active","transcript_path"]`)에는 `agent_id`가 없어 메인 세션 종료와 서브에이전트 종료를 키 존재 여부만으로 구분 가능.)
- 결정: L2 훅을 settings.json에 둔다 (근거: `PreToolUse`·`SubagentStart`·`SubagentStop`·`Stop` 네 이벤트 모두 워크플로 `agent()` 서브에이전트 내부에서 정상 발화했고, stdin JSON의 `agent_id`/`agent_type` 키로 메인 세션과 서브에이전트를 구분해 로그를 필터링할 수 있다. 별도의 에이전트 frontmatter hooks나 verify-stage 사후검증 없이도 settings.json 수준의 훅만으로 옵저버빌리티를 확보할 수 있으므로 대체 방식은 불필요.
  참고: 이 러너에서도 spike-2와 동일하게 `.claude/settings.json`의 `permissions.allow` 7개가 "workspace has not been trusted"로 무시되었으나, `--permission-mode dontAsk`가 모든 툴 호출을 승인해 훅 발화 자체에는 영향이 없었다.)
