# ADR-003 schema 신뢰도

- nulls: **0/20** (opus 0/10, sonnet 0/10) · rejects: **20/20** (opus 10/10, sonnet 10/10 — 두 모델 모두 스니펫의 타임존 버그를 정확히 찾아 100% reject 판정, approve는 0건) · 비용 **$1.5526413500000003** (전체 20 agent 1회 실행, `num_turns: 2`, `duration_ms: 85092`(≈85초))
  (Step 3 지시대로 `pipeline`의 결과 전체 `out` 배열을 `{ marker, total, nulls, rejects, out }`로 반환하도록 워크플로를 작성해 1회 실행만으로 모델별 귀속까지 확인했다. 인덱스 짝수=opus, 홀수=sonnet 매핑으로 opus/sonnet 각 10개씩 전부 파싱 성공(null 없음)했고, `must_fix`/`verified` 등 nested array·enum 필드도 모든 항목에서 스키마 그대로 채워졌다.)
- **결정**: null 발생률이 20/20 중 0건으로 이번 표본에서는 재시도 로직을 검증할 기회 자체가 없었다. 스펙 §7.5의 "null 시 해당 리뷰어 1회 재spawn" 정책은 **유지**한다(표본이 20회 1세트뿐이라 신뢰구간이 넓고, opus/sonnet 모두 0%였다는 결과만으로 재시도 로직을 제거하기엔 근거가 부족함). 복잡한 schema(중첩 배열 `must_fix[]` + object required 필드 + enum 3종)에서도 실패가 없었으므로 스키마 복잡도 자체가 신뢰도의 주 원인은 아니라고 잠정 결론. 모델 고정은 불필요 — opus/sonnet 둘 다 이번 표본에서 동일하게 100% 성공·100% 정답(reject)이었다.
