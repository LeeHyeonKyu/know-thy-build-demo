# ADR-004 러너 자원

- 실행: `spike-4-resources.yml`, 표준 `ubuntu-latest` 러너, `trust-workspace`를 `setup-claude` 직후에 추가해 playwright-MCP 스텝을 trusted 상태로 돌렸다(컨트롤러 지시 반영).

  ## 1차 시도(run [34576307302](https://github.com/LeeHyeonKyu/know-thy-build-demo/actions/runs/34576307302)) — 실패

  `env up`는 정상 완료(`env_up=60s`, `Mem: total 7937 / used 1466 / free 2280 / available 6471` MB)했지만 `full (unit+integration)` 스텝에서 **브리프가 예상하지 못한 이유로 실패**했다: `npm test`(vitest)가 기본 test glob으로 `e2e/smoke.spec.js`까지 집어 먹어 `Error: Playwright Test did not expect test() to be called here`로 죽었다(vitest 자체 테스트 2개는 통과 — `2 passed`). `docker-compose.test.yml`/`db.test.js`/e2e 파일은 브리프 그대로였고, vitest가 e2e 디렉토리를 제외하는 설정이 브리프에 없었던 것이 원인. `deep`·MCP 스텝은 실행되지 못했다.

  **수정**: `vitest.config.js`를 추가해 `test.exclude`에 `e2e/**`를 넣어 vitest가 Playwright 스펙을 건드리지 않게 했다(브리프에 없는 파일이지만, 브리프가 만든 구성의 결함을 고치기 위한 최소 변경). 커밋 후 1회 재실행(총 2회, 규칙상 상한 준수).

  ## 2차 시도(run [34576571041](https://github.com/LeeHyeonKyu/know-thy-build-demo/actions/runs/34576571041)) — 성공

  전 스텝 성공(`✓ env up`, `✓ full`, `✓ deep`, `✓ claude drives playwright MCP headless`), 잡 총 소요 1m14s.

  | 항목 | 값 |
  |---|---|
  | env_up | 36s |
  | full (unit+integration) | 2s |
  | e2e (deep) | 2s |
  | 메모리(env up 직후, `free -m`) | total 7938MB · used 1224MB · free 2454MB · available **6714MB** |
  | 메모리(e2e 직후, `free -m`) | total 7938MB · used 1385MB · free 2252MB · available **6553MB** |
  | playwright MCP headless 결과 | `.result` = `"{\"ok\":true}"` → **ok**(healthz 응답 본문 `{"ok":true}` 그대로 회신) |
  | `.mcp.json` 승인 문제 | **없었음** — `trust-workspace`를 MCP 스텝 이전에 실행해뒀기 때문에 1차 시도에서 이미 `enableAllProjectMcpServers` 없이 MCP 서버가 바로 로드됐다. 이 설정을 추가할 필요가 없었다(브리프의 대안 분기는 발동되지 않음 — 그대로 기록). |

- **결정**:
  - 표준 `ubuntu-latest` 러너로 compose(postgres) + express 앱 + playwright chromium + claude(playwright MCP)를 **동시에 돌리는 M2 시나리오는 가능**하다 — env_up(36s, chromium 설치 포함)까지 마친 시점의 가용 메모리가 6.7GB(전체 7.9GB 중), e2e 직후에도 6.5GB로 여유가 크다. CPU/시간 경합도 관측되지 않았다(full 2s, e2e 2s — 앱/테스트 자체가 가벼워 병목이 아니었음에 유의; 실제 프로덕션 앱 규모에서는 재측정 필요).
  - `runtime_budget_min` 기본값: 이번 실측(env_up+full+e2e+mcp ≈ 1분14초, 전체 job)은 매우 가벼운 데모 앱 기준이라 그대로 기본값으로 쓰기엔 낙관적이다. 여유를 두어 **runtime_budget_min 기본값 10분**을 제안한다(chromium 설치·docker pull 캐시 미스 시의 변동, 실제 앱 규모의 unit/e2e 테스트 시간을 감안한 버퍼).
  - 대형 러너(large runner) 필요 조건: 이번 측정에서는 **불필요**로 판단한다(가용 메모리가 표준 러너 총 메모리의 80%대를 유지, 디스크/CPU 경합 징후 없음). 실제 앱의 e2e 스위트가 다수의 브라우저 컨텍스트를 병렬로 띄우거나, `available` 메모리가 관측치 대비 크게 줄어드는 워크로드로 커지면(예: postgres에 대량 fixture 로드 + 여러 chromium 워커 병렬) 대형 러너 전환을 재검토한다.
  - vitest가 기본적으로 `e2e/**/*.spec.js`까지 스캔한다는 점은 스펙/브리프 템플릿에 **`vitest.config.js`의 `test.exclude: ["e2e/**"]`를 표준 스캐폴드로 포함**시켜야 한다는 후속 조치로 남긴다.
