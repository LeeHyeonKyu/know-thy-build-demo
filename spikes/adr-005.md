# ADR-005 구독 토큰의 usage limit

- **실행 취소**: `spike-5-usage.yml`(부하 잡, `/spike-schema-dispatch` x3)을 워크플로만 작성·커밋·트리거(run [34577204905](https://github.com/LeeHyeonKyu/know-thy-build-demo/actions/runs/34577204905), 시작 2026-09-11T08:02:18Z)했으나, 사람(@LeeHyeonKyu)이 구독 7일 창이 94%에 도달한 것을 확인하고 **직접 취소**(종료 2026-09-11T08:03:39Z, `conclusion: cancelled`, 총 경과 약 1m21s)했다. 부하 잡의 `.spike/usage-*.json`/`.spike/total-tokens`는 생성되지 못했다 — 취소 시점에 "burn ~1M tokens" 스텝이 실행 중이었다(`upload-artifact`는 `if: always()`로 완료됐지만 burn 스텝 자체가 중단됨).

- **사람 관측(수동, `/usage`)**:
  - before: **92%** (오늘 전체 스파이크 실행 시작 시점, 7일 창)
  - after: **94%** (Spike 0~8 실행 후, 부하 잡 실행 전)

- **교란 요인(confound)**: 사람의 인터랙티브 로컬 세션이 동일 기간에 함께 실행되고 있었다. 따라서 관측된 `+2%`는 **CI(Spike 0~8) 귀속분의 상한(upper bound)**일 뿐, CI만의 순수 소모량으로 분리해 측정한 값이 아니다(사람 세션과 CI 세션이 같은 7일 창을 공유해서 발생).

- **CI 소모 토큰/비용(참고, 상한 산정의 분모)**: 오늘 실행된 스파이크 중 `total_cost_usd`/`usage`를 stdout에 남긴 3개 run의 실측 합계(로그에서 직접 확인, `gh run view --log`).

  | run | workflow | input_tokens | output_tokens | cache_creation_input_tokens | cache_read_input_tokens | total_cost_usd |
  |---|---|---:|---:|---:|---:|---:|
  | [34573333760](https://github.com/LeeHyeonKyu/know-thy-build-demo/actions/runs/34573333760) | spike-0-auth | 2 | 144 | 9,214 | 18,531 | 0.0429652 |
  | [34573640589](https://github.com/LeeHyeonKyu/know-thy-build-demo/actions/runs/34573640589) | spike-2-p-workflow | 2 | 134 | 1,045 | 28,790 | 0.0890815 |
  | [34574561593](https://github.com/LeeHyeonKyu/know-thy-build-demo/actions/runs/34574561593) | spike-3-schema | 4 | 12,673 | 31,051 | 62,492 | 1.5526414 |
  | **합계** | | **8** | **12,951** | **41,310** | **109,813** | **1.6846881** |

  나머지 스파이크(1, 4, 6, 6b, 7, 7b, 8 — 총 9개 run)는 워크플로 yml이 `.result`/`.permission_denials`/타이밍만 `jq`로 출력하고 `total_cost_usd`/`usage`는 stdout에 남기지 않아, 실행 로그만으로는 비용을 복원할 수 없다(아티팩트의 `.spike/out.json` 원본을 개별 다운로드해야 함 — 이번 관측 범위 밖). 따라서 위 표의 **$1.68 / 약 13K 토큰은 오늘 CI 소모의 전체가 아니라 부분 합**이며, 실제 CI 귀속분은 이보다 크다.

- **결론**: 구독 창을 소모한다(상한 추정 +2% / ~$1.68 CI, 단 CI 전체가 아닌 3개 run만의 부분 합계이므로 실제 CI 귀속 비율은 이 하한보다 높을 수 있음). 사람 세션과 CI 세션을 같은 창에서 분리 측정하지 않는 한 정확한 귀속은 불가능하다(교란 요인 참조).

- **결정**: 구독 토큰이 운영 전제다. factory는 소비를 제한하지 않고 **보고**한다 — 잡마다 stdout JSON의 usage/total_cost_usd/modelUsage를 run 기록에 남기고, 이슈 단위·주간 단위로 합산해 `factory status`와 retro/digest에 표시한다. CHARTER의 예산 상한은 선택 사항이며 기본값은 꺼짐(unset); 켜면 초과 시 새 claim만 거부한다. 한도·토큰 관리는 사람이 한다. 부하 잡은 취소됨(run 34577204905).

  후속 조치 제안: 모든 스파이크/factory 워크플로가 `total_cost_usd`·`usage`를 `.spike/`(또는 표준 아티팩트 경로)에 항상 남기도록 템플릿을 통일하면, 이런 사후 비용 합산이 로그 grep만으로 가능해진다(이번 관측에서 9개 run이 이 표준을 따르지 않아 부분 합계에 그침).
