# ADR-008 신뢰되지 않은 러너에서의 deny

- project-only: deny 적용 **yes** · cli-settings: deny 적용 **yes** · trusted(hasTrustDialogAccepted): deny 적용 **yes**, allow 경고 사라짐 **yes**
  (세 매트릭스 레그 모두 `git ls-remote --heads origin deny-probe-should-never-exist`가 빈 출력으로 끝나 원격 브랜치가 전혀 생성되지 않았음을 확인. `force_push`는 3/3 "denied". 안전 프로브 결과 정리를 수행할 필요 없었음.)

  - **project-only** (프로젝트 `.claude/settings.json`의 `permissions.deny`만, `--settings` 없음, trust 부트스트랩 없음): `{"echo": "denied", "force_push": "denied"}` — **echo까지 함께 거부됨**. `permission_denials`에 두 Bash 호출 모두 기록(`tool_name: Bash`, 각각 `echo DENY_PROBE_MARKER...`와 `git push --force...`). "Ignoring 7 permissions.allow entries ... this workspace has not been trusted." 경고 여전히 출력. `num_turns: 3`. 모델의 최종 답변: "Bash 자체가 이 세션(don't-ask 모드)에서 차단되어 있어 둘 다 실행되지 않았다"는 취지로 스스로 원인을 보고.
  - **cli-settings** (`--settings .factory-ci-settings.json`으로 deny만 담긴 파일 추가 전달): `{"echo": "denied", "force_push": "denied"}` — project-only와 동일하게 **둘 다 거부**. `permission_denials`에 두 호출 모두 기록. "Ignoring 7 permissions.allow entries ..." 경고도 **여전히 출력**됨 — 즉 `--settings`는 project `.claude/settings.json`을 대체하지 않고 병합되며, project settings의 allow는 여전히 untrusted 사유로 무시된다. `num_turns: 3`.
  - **trusted** (`~/.claude.json`의 `projects[cwd].hasTrustDialogAccepted: true` 부트스트랩): `{"echo": "ran", "force_push": "denied"}` — **echo는 정상 실행**(`.spike/deny-probe.txt`에 `DENY_PROBE_MARKER` 기록됨 확인)되고 **force_push만 선택적으로 거부**됨. "Ignoring" 경고 **완전히 사라짐**(grep 결과 0건). `permission_denials`에는 force_push 호출 1건만 기록. `num_turns: 5`.

  **핵심 발견**: project-only·cli-settings 두 모드에서는 `permissions.deny`가 있으면 (allow가 untrusted로 무시된 상태와 맞물려) `--permission-mode dontAsk`가 **Bash 전체를 기본 거부**로 전환한다 — deny 패턴에 안 걸리는 `echo`조차 막힌다. 이는 스펙이 기대한 "정확히 force-push만 막는" 선택적 deny가 아니라 "untrusted + deny 존재 시 Bash 전면 봉쇄"에 가깝다. **trusted**로 전환해야만 allow가 정상 작동해 echo는 통과하고 deny만 선택적으로 걸린다(스펙이 원래 기대한 동작과 일치하는 유일한 모드).

- **결정**: **trust 부트스트랩 스텝을 추가**한다 (project-only/cli-settings 둘 다, "선택적 deny"가 아니라 "Bash 전면 봉쇄"라는 부작용이 있어 일반 워크플로에는 부적합 — 정상적으로 허용돼야 할 Bash 호출까지 막히면 파이프라인이 동작하지 않는다). `~/.claude.json`에 `projects[$CLAUDE_PROJECT_DIR].hasTrustDialogAccepted: true`를 쓰는 스텝을 모든 factory CI 워크플로의 공통 setup(`setup-claude` 액션 또는 별도 `trust-workspace` 스텝)에 넣고, 그 위에서 project `.claude/settings.json`의 `permissions.deny`(L2)를 사용한다. `--settings .factory/ci-settings.json`는 trust 부트스트랩과 무관하게 project settings에 **병합**되므로 필수는 아니지만, deny 규칙을 워크플로별로 오버라이드/확장하고 싶을 때 보조 수단으로 유지할 수 있다.
- **스펙 영향**: §6.3에 "CI 러너는 각 워크플로 실행 전에 trust 부트스트랩(`hasTrustDialogAccepted: true`)을 거쳐야 하며, 그렇지 않으면 `permissions.deny`가 있는 경우 Bash 전체가 봉쇄되고 없으면 `permissions.allow`가 전부 무시된 채 dontAsk가 모든 호출을 통과시킨다(ADR-002/ADR-008)"를 명시. §4.2.1의 4번째 플래그(신뢰 관련 플래그)는 `--settings` 단독이 아니라 "trust 부트스트랩 + project deny" 조합으로 기술.
